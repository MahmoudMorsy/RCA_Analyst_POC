# RCA Analyst POC v0.8.2 — Release Notes

## Purpose

**Live-TC17 semantic-repair and RCA-routing correction.** v0.8.2 keeps the v0.8 semantic-compiler / deterministic-compliance architecture and fixes failures exposed by the TC17 v0.8.0 live run.

## Live TC17 findings

The v0.8.0 run was safe but unsuccessful:

- the 4B compiler recognized the mixed German/English nested condition in prose, including the outer AND, inner OR and ServiceMode negation, but returned `condition=null`, `required_behavior=null` and `normative_type=AMBIGUOUS`;
- Python correctly blocked deterministic execution because the material source clauses were not represented in executable IR fields;
- the single 27B semantic-arbitration call returned essentially the same prose-only pseudo-repair instead of a complete replacement IR;
- the case therefore remained `APPLICABILITY UNKNOWN / NOT EVALUABLE` for all three requirements;
- the RCA router then unnecessarily launched a second 27B call because contextual/symptom evidence was tagged as `RCA_CONTEXT` / `DIAGNOSTIC`, despite there being no mechanism evidence.

The v0.8.0 run consumed about 50.8 minutes total, of which about 37.4 minutes were the two 27B calls.

## Changes

### 1. Compiler materialization contract

The semantic compiler prompt now states explicitly that:

- mixed language, unusual sentence order and nested Boolean logic are not ambiguity by themselves;
- if the model can explain the semantics in notes, it must encode them into the actual IR fields;
- clear `shall` obligations are not `AMBIGUOUS` merely because the precondition is linguistically complex;
- clear IF/state requirements require a non-null condition;
- clear mandatory/prohibitive obligations require a non-null required behavior;
- `shall remain` requires both required behavior and persistence semantics.

### 2. Strict 27B arbitration replacement contract

`SemanticArbitrationResponse` now rejects pseudo-repairs. Any returned Requirement IR must:

- not remain `AMBIGUOUS`;
- contain only VERIFIED material source clauses;
- provide required behavior for mandatory/prohibitive requirements;
- represent every material source-clause semantic ID in executable IR fields.

If the source genuinely cannot be resolved, the arbitrator must leave the requirement out of the repair list and return the issue IDs in `unresolved_issue_ids`.

### 3. Dedicated mechanism role

A new evidence semantic role `MECHANISM` represents positive current-case mechanism/process evidence.

The compiler is instructed that:

- a ticket title is not mechanism evidence;
- a symptom statement is not mechanism evidence;
- an expected-vs-observed output mismatch is not mechanism evidence;
- an ordinary signal observation is not `DIAGNOSTIC` merely because it is diagnostically useful.

### 4. RCA routing hardening

The deterministic router now:

- treats `RCA_CONTEXT` as non-routing;
- accepts semantic `DIAGNOSTIC` only when the authoritative source is Current BZD / Diagnostics;
- accepts semantic `HISTORICAL` only when the authoritative evidence class is historical;
- uses `MECHANISM` for positive current-case mechanism routing;
- refuses to treat a point-state observation of a requirement output signal as mechanism evidence.

This keeps TC17 out of the deep RCA stage when only the compliance mismatch is known.

### 5. RCA Evidence Packet source-class guard

Direct observations mislabelled by an LLM as diagnostic/history are no longer copied into the diagnostic/historical packet sections unless their authoritative source class matches.

## Expected TC17 behavior

For the unchanged TC17 fixture, the target remains:

- REQ-1701: APPLICABLE / VIOLATED;
- REQ-1702: NOT APPLICABLE;
- REQ-1703: NOT APPLICABLE;
- no unsupported mechanism hypothesis;
- no 27B RCA call unless additional positive mechanism evidence is supplied;
- at most one 27B semantic-arbitration call if the fast compiler/verifier cannot resolve the requirement IR cleanly.

## Validation

Working-tree automated suite after the TC17 fixes: **165 passed**.
