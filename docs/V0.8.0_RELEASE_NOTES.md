# RCA Analyst POC v0.8.0 — Release Notes

## Release type

**Architecture release.** v0.8.0 replaces the v0.7.x always-on decomposed 27B topology with an adaptive semantic-compiler architecture.

## Why v0.8.0 exists

Live TC12 and TC17 runs invalidated v0.7.1 as a production baseline.

### TC12 findings

- 8 model calls were made.
- Total model time was approximately **10,784 s / 179.7 min**.
- Three sequential 27B calls consumed approximately **166.5 min**.
- REQ-1204 regressed from the frozen deterministic timing result to `APPLICABILITY UNKNOWN / NOT EVALUABLE`.
- Decimal trace timestamps were corrupted after intake canonicalization: values such as `99.900 s` and `100.000 s` were treated as numbered-list prefixes.

### TC17 findings

- Total model time was approximately **3,554 s / 59.2 min**.
- The two 27B calls consumed approximately **51 min**.
- REQ-1701 was incorrectly reported `SATISFIED` although the requirement demanded `StarterEnable=TRUE` and the correlated observation was `FALSE`.
- REQ-1702 and REQ-1703 were downgraded to unknown even though complete relevant interval evidence made their applicability conditions false.
- The 4B requirement normalization dropped the `ServiceMode is not ACTIVE` clause from the nested condition.
- The 27B later understood the original requirement but still emitted an internally contradictory sufficiency label, which the Python layer trusted too much.

The conclusion was architectural: v0.7.x multiplied expensive reasoning while still allowing model-produced compliance labels to dominate deterministic truth.

## Core architecture change

v0.8.0 enforces:

> **LLM semantic compilation -> verified Requirement IR/evidence annotations -> deterministic Python compliance -> conditional deep RCA.**

### One normal 4B semantic-preparation call

Requirement compilation and free-text evidence annotation are performed together at case level. This replaces the always-on Atomic Claims + Requirement Language sequence for the production path and avoids per-sentence model calls.

### Requirement IR

Free-form requirements are compiled into a declarative IR containing:

- recursive Boolean condition AST;
- trigger/event semantics;
- required behavior;
- timing;
- persistence;
- relationships/exceptions;
- semantic IDs and source-clause provenance;
- explicit unresolved semantics.

Python does not parse requirement prose.

### Compiler self-audit

The compiler must return source clauses mapped to semantic IDs. Python checks that material clauses are represented in the IR. This guards directly against the TC17 dropped-clause failure.

### Context-safe evidence semantics

Human statements such as `BatteryVoltage remained 12.2 throughout the interval` are not automatically promoted to whole-case interval evidence. The model annotates the claim and resolves its scope where possible. Persistent evidence is executable as `INTERVAL_STATE` only when scope is resolved.

### Conditional 27B semantic arbitration

All materially unresolved semantics are batched into **one case-level 27B call**. There is no per-sentence arbitration and no repeated 27B semantic retry loop. If the source remains ambiguous, compliance remains conservative.

### Python owns compliance

The deterministic engine executes verified IR/facts and calculates:

- applicability;
- state predicates;
- nested Boolean conditions;
- transitions;
- persistence;
- timing;
- evidence sufficiency;
- parent/inherited applicability;
- final verdicts.

An LLM cannot overwrite these results.

### Conditional 27B RCA

Deep RCA runs only when mechanism-oriented evidence exists. A bare compliance failure does not trigger it.

The RCA model receives a compact RCA Evidence Packet, not the full raw case. Original natural-language requirements are intentionally excluded by default so RCA synthesis cannot reopen semantic interpretation.

## Parser correction

`IntakeCanonicalizer._strip_label` now requires whitespace after a numbered-list marker. Therefore:

```text
1. Set IgnitionState to ON.  -> Set IgnitionState to ON.
99.900 s Signal = X         -> preserved unchanged
100.000 s Signal = Y        -> preserved unchanged
```

The v0.8 production parser also disables deterministic natural-language interval promotion. Phrases such as `remained ... throughout ...` remain unstructured language evidence until the semantic preparation stage resolves them.

## Model-call budget

Expected production budget:

- routine case: 1×4B semantic preparation, 0×27B;
- complex compliance semantics: +1×27B arbitration;
- real RCA evidence: +1×27B RCA;
- hard semantics + real RCA: normally at most 2×27B total.

Requirement count alone no longer triggers 27B chunking.

## GUI / CLI changes

- Added v0.8 semantic-preparation, semantic-arbitration, and conditional-RCA controls.
- Semantic preparation defaults ON.
- If no fast model is configured, the primary model performs the one semantic-preparation call rather than falling back to Python NLP.
- Added CLI switches:
  - `--disable-semantic-preparation`
  - `--disable-semantic-arbitration`
  - `--disable-rca-synthesis`
- Removed v0.7 Phase-A chunk/large-case/repair knobs from the visible production GUI while retaining their config fields for migration compatibility.
- Final 4B review is now optional wording audit only and defaults OFF.

## Regression coverage

v0.8.0 adds exact v1.3 overnight fixtures for TC12 and TC17 plus routing/contract tests covering:

- decimal timestamp preservation;
- no Python promotion of natural-language interval scope;
- dropped compiler clause detection;
- TC12 1100/800/+300 timing violation;
- TC17 nested-condition violation;
- NOT APPLICABLE override requirements;
- zero-27B clean TC17 route;
- exactly one 27B arbitration on material semantic defect;
- exactly one 27B RCA call when RCA context is present;
- no original requirement wording in the default RCA packet.

## Compatibility and frozen semantics

- The validated state/transition/interval semantics remain unchanged.
- Missing evidence remains conservative.
- Historical tickets remain non-normative.
- Hypotheses still require current-case mechanism support.
- A compatibility-only v0.7.1 pipeline branch remains for older tests/adapters; GUI/CLI v0.8 use the new branch.

## Automated verification

The working-tree release suite passes **160 tests** before packaging. The final release process also requires compile-all, fresh-extracted ZIP tests, ZIP integrity, cache cleanup, and SHA-256 generation.
