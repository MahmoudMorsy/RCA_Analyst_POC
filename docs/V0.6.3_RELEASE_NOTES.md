# v0.6.3 release notes

v0.6.3 refines the multi-model boundary introduced in v0.6.0 based on the real TC5 `4B Always` run.

## Intake semantics

Qwen3.5-4B now performs semantic source-availability normalization instead of placing every recognized sentence into a content bucket. Requirements, historical tickets, diagnostics/BZD, and traces are classified as `PRESENT`, `ABSENT`, `UNKNOWN`, or `NOT_MENTIONED`. An explicit absence/uncertainty statement carries its verbatim `source_span` but is metadata, never engineering evidence.

The 4B intake path does not use multilingual absence-sentinel phrase lists. Python enforces only the structured contract produced by the model: a non-PRESENT source cannot contain evidence blocks, and source spans must still be backed by the original raw input. The legacy deterministic template parser keeps narrow standardized none-marker handling for cases where 4B intake is intentionally bypassed/off.

The intake schema also adds `user_instructions` so instructions such as "do not assume trace completeness" are preserved separately from evidence and from genuinely unclassified text.

## Final review semantics

The fast final reviewer is now explicitly told that relevance and evidentiary sufficiency are independent. A response observation may be directly relevant to a timing requirement while incomplete event coverage still makes the verdict `NOT EVALUABLE`.

## UTF-8 streaming

Cancellable LM Studio SSE streams are decoded explicitly as UTF-8. This prevents the mojibake observed in the v0.6.2 TC5 report (`â`, `â`) and protects German characters such as `ä`, `ö`, `ü`, and `ß`.

## Thinking mode

Qwen3.5 intake Thinking remains OFF by default. The release first improves schema, instructions, examples, and constrained enums; Thinking should be enabled only if real-case benchmarks show a measurable accuracy benefit worth its latency.
