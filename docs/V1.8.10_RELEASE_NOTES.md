# RCA Analyst v1.8.10 Release Notes

**Application:** v1.8.10  
**Embedded RCA Core:** v0.8.9 candidate  
**Built from:** v1.8.9

## Why v1.8.10 exists

The first exact-package v1.8.9 27B full-suite RunPod attempt exposed two independent failure classes.

First, TEST-007 produced an arbitration field-contract error:

```text
Arbitration patch omitted targeted fields for REQ-601: ['required_behavior']
```

That `ValueError` escaped testcase scope, converted the whole bundle to `FAILED`, and prevented all later testcases from executing. The exported session also preferred the partial batch result over the run-level failure, hiding the original exception until `failure.json` was retrieved separately.

Second, several otherwise valid cases, including TEST-012, were blocked by false independent-verifier mismatches. Compiler and verifier agreed on executable signal/operator/value/event semantics, but Python included descriptive `process_description` text and arbitrary persistence-scope wording in semantic fingerprint equality.

v1.8.10 fixes those contracts without weakening evidence semantics or moving natural-language interpretation into Python.

## RCA Core v0.8.9 changes

### Arbitration failure is conservative, not fatal

Semantic arbitration remains a bounded repair stage. If its returned patch violates the field-level repair contract, Python now:

1. preserves the raw model attempt;
2. rejects the patch atomically;
3. keeps the pre-arbitration Requirement IR/evidence state;
4. retains the material semantic-integrity issues;
5. continues to deterministic compliance conservatively.

An invalid repair can therefore yield UNKNOWN / NOT EVALUABLE where appropriate, but it no longer crashes the testcase.

### Field-level explicit unresolved arbitration

Every arbitration target field is still strict. A targeted field may be omitted only when **all material issue IDs governing that exact field** are explicitly returned in `unresolved_issue_ids`.

This supports the intended contract:

```text
field repaired            → merge target field
field genuinely unresolved → explicit unresolved issue IDs
silent omission            → reject patch
```

No omitted field is inferred from requirement prose.

### Rejected arbitration output is preserved

A schema-valid arbitration response is recorded as a pipeline attempt before field-contract validation. If field validation rejects it, Live Pipeline output records the rejection reason, rejected structured response, model-call metadata, finish reason and transport. The pipeline result keeps the raw attempt for later forensic analysis.

Provider/schema failures already preserve raw provider output through `ModelGatewayError` structured attempts; this release closes the post-schema semantic-contract observability gap.

### Semantic verifier equality uses executable semantics

`required_behavior` equality now compares only executable semantic fields:

- signal;
- operator;
- value;
- event semantics.

It does **not** compare:

- `process_description`;
- `source_phrase`;
- semantic IDs;
- notes.

Those remain provenance/audit fields but cannot create false semantic disagreement.

### Persistence scope normalization

Persistence equality no longer compares arbitrary model wording byte-for-byte. The structured scope field is normalized into coarse structural categories such as `WHILE_CONDITION`, `CASE_EVALUATED_INTERVAL`, explicit scope, or unspecified scope. This makes `WHILE_CONDITION` equivalent to model wording such as `while <compiled condition>` without parsing the authoritative requirement prose.

Frozen point/transition/interval evidence semantics remain unchanged.

## Application v1.8.10 changes

### Testcase failure isolation

Sequential bundle/regression execution now places both pipeline construction and pipeline execution inside the testcase-local isolation boundary.

For every testcase:

```text
unexpected testcase exception
        ↓
record testcase FAILED
persist failure artifact
update lifecycle/result
        ↓
continue next testcase
```

Only run-level conditions such as explicit cancellation or an outer backend/process failure stop the requested suite.

The overall bundle reaches `COMPLETED` when all requested testcase slots were attempted, even when individual cases are `FAILED`. Execution completion remains distinct from semantic acceptance.

### Generic failure forensic payload

Unexpected testcase failures now persist:

- `case_id`;
- exception type;
- message;
- Python traceback;
- partial testcase pipeline snapshot.

The Web failed-testcase view surfaces exception type/message/traceback and the Structured JSON view retains the complete failure payload.

### Session preservation

When a run has both a partial result and a run-level failure, session autosave preserves the normal result envelope and adds `run_failure` rather than choosing one and discarding the other. Per-testcase failures remain embedded in `result.cases`.

## Regression coverage

v1.8.10 adds regressions for:

- descriptive `process_description` not affecting verifier equality;
- structurally equivalent persistence scope normalization;
- field-level explicit unresolved arbitration;
- rejected arbitration continuing conservatively with raw attempt preserved;
- generic testcase exception isolation followed by successful later testcase execution;
- generic failure exception/traceback/partial-pipeline persistence;
- session preservation of partial result plus run-level failure;
- Web exception/traceback rendering contract.

The complete automated release suite contains **232 tests**. The exact final ZIP passed all **232 tests** again from a clean fresh extraction, plus Python compile, Web JavaScript syntax, FastAPI health/config/capabilities smoke and ZIP-integrity/package-content audits.

## Release acceptance status

Automated software/regression gates are required but do not freeze RCA Core v0.8.9. The next live gate is the exact v1.8.10 package on RunPod with stable 27B critical-semantic routing for the entire suite.

The rerun must verify both dimensions independently:

- **execution:** one testcase failure must not prevent later testcases from running;
- **semantic acceptance:** TC12, TC17 and TC21 remain primary semantic/integration anchors, while all frozen earlier evidence invariants remain intact.
