## Why v1.8.11 exists

The exact v1.8.10 package completed the full 17-case RunPod suite with the critical semantic roles physically resolved to Qwen3.8-27B. Batch continuation and the earlier TC12/TC17 verifier defects were fixed: all 17 cases executed, TC12 and TC17 passed their expected live targets, and 11/17 cases passed semantic acceptance. ## RCA Core v0.8.10 changes

### 1. VERIFIED verifier fingerprints must be structurally complete

The TEST-016 live verifier declared REQ-1601 VERIFIED in prose but omitted the executable `required_behavior.operator` and `value`. v0.8.9 therefore compared `OTHER/""` against the compiler's `EQ/ACTIVE` and produced a false semantic mismatch.

v0.8.10 makes a VERIFIED verification item a schema-level contract: signal-based required behavior requires an executable operator/value, BECOMES triggers require signal/event/value, timing requires `limit_ms`, and returned relationships require type/target. An incomplete VERIFIED fingerprint is rejected by structured-output validation and enters the existing bounded retry path instead of becoming a false compiler disagreement. PARTIALLY_RESOLVED/UNRESOLVED verifier items may still represent genuine incompleteness.

### 2. Requirement persistence scope is a canonical semantic domain

Requirement-side persistence scope is now distinct from evidence observation type. `RequirementPersistenceIR.scope` uses a canonical vocabulary:

- `WHILE_CONDITION`
- `CASE_EVALUATED_INTERVAL`
- `EXPLICIT_RESOLVED_SCOPE`
- `UNSPECIFIED`

Known structural aliases such as `WHILE_CONDITION_ACTIVE` and `while <compiled condition>` normalize to `WHILE_CONDITION`. Evidence-domain values such as `INTERVAL_STATE` are rejected rather than accepted as requirement semantics. This addresses TEST-015 and TEST-021 without weakening interval-evidence requirements.

### 3. Atomic arbitration tolerates redundant unchanged fields

TEST-019 returned the correct relationship repairs but redundantly echoed an unchanged `source_clauses` field. v0.8.9 rejected the entire response merely because the untargeted field was present.

v0.8.10 now distinguishes:

- untargeted field **changed** → reject the repair;
- untargeted field supplied but structurally identical to the current value → ignore it and record a contract diagnostic.

The merger still copies only Python-approved target fields, so arbitration remains field-atomic and non-regressive.

### 4. Newly-created semantics automatically require provenance audit repair

TEST-007 arbitration correctly created the missing REQ-602 required behavior, but the new `semantic_id` had no matching `source_clauses` audit entry. v0.8.10 automatically adds `source_clauses` as a companion arbitration target when a repair creates a previously absent executable semantic field and the current audit inventory lacks the corresponding semantic role.

Python does not infer clause language; the model must return the complete source-clause inventory in the same bounded arbitration call.

### 5. RCA packet includes referenced canonical direct observations

TEST-018 had deterministic requirement results referencing explicit direct observations such as `ActuatorCommunication = LOST`, but those canonical structured observations were absent from `verified_evidence` because they required no language annotation.

v0.8.10 deterministically includes referenced canonical `DIRECT_OBSERVATION` items with explicit signal/value/observation structure in the RCA Evidence Packet. This preserves current-case mechanism evidence without asking the LLM to reinterpret the trace.

### 6. Rejected arbitration diagnostics are persisted

A rejected arbitration response now records the exact contract-rejection reason in both the pipeline attempt's `retry_diagnostics` and a `SEMANTIC_ARBITRATION_CONTRACT_REJECTED` validation issue, in addition to preserving the raw response.
