# RCA Analyst POC v0.8.1 — Release Notes

## Release type

**Live-run reliability correction.** v0.8.1 keeps the v0.8 semantic-compiler / deterministic-compliance architecture and fixes failures exposed by the first live TC12 v0.8.0 run.

## Live TC12 v0.8.0 findings

The failed session showed that the deterministic parser correction was successful: decimal timestamps `99.900`, `100.000`, `100.600`, and `101.100` survived canonicalization correctly.

The failure occurred later in 4B semantic preparation:

1. the case-level `SemanticPreparation` response exceeded the loaded Qwen3.5 context/output envelope and both bounded attempts ended with `finish_reason=length` at an 8192-token total;
2. the second attempt happened to produce parseable JSON for only part of the requirement set but used JSON `null` for optional string fields such as `required_behavior.event`, which the v0.8.0 Pydantic contract rejected;
3. more importantly, the same retry silently omitted explicit IF conditions from REQ-1201 and REQ-1202 while also omitting those clauses from its own source-clause audit. This proved that compiler self-audit alone cannot detect every semantic omission.

## Corrections

### Bounded semantic-preparation batching

Small cases continue to use one compact case-level semantic-preparation call.

Larger cases are automatically split into bounded **4B requirement-compilation batches**. Each batch:

- compiles at most five ordinary requirements;
- never splits one requirement;
- receives all authoritative requirement texts as read-only relationship context;
- returns only the Requirement IRs for the explicitly selected batch;
- uses the narrower `RequirementCompilationBatch` schema to reduce schema/context overhead.

Natural-language evidence is then annotated once using a separate narrow `EvidenceAnnotationBatch` schema. Requirement count still never causes a 27B call.

For TC12 this produces two five-requirement compiler batches plus one evidence-language batch instead of trying to emit ten IRs and all evidence annotations in one 8k-context response.

### Null-safe optional semantic fields

LLM JSON `null` is now normalized to the existing empty-string sentinel only for semantic fields whose contract already defines an empty string as "not supplied" (for example `required_behavior.event`). This is envelope normalization, not semantic repair. Material omissions such as a missing predicate signal or semantic linkage remain detectable downstream.

### Independent 4B semantic verification

After Requirement IR compilation, one compact independent 4B verification pass compares every original requirement with its compiled IR.

The verifier treats the IR as untrusted and checks preservation of:

- IF/state conditions;
- WHEN/UPON triggers;
- nested AND/OR/NOT;
- required behavior and prohibitions;
- timing;
- persistence/non-occurrence;
- exceptions;
- explicit requirement relationships/inherited scope.

A mismatch becomes a material semantic issue and is included in the existing **single case-level 27B semantic arbitration** packet. No per-requirement 27B call is introduced.

If 27B arbitration repairs an IR, the compact 4B verifier is run once again on the repaired representation. Remaining mismatches stay conservative; there is still no second 27B semantic retry.

### Prompt compaction

Semantic-preparation payloads no longer serialize every empty/internal evidence field. Requirement references, language evidence, and deterministic trace facts use compact purpose-specific envelopes, reducing prompt size substantially.

## Model-call topology

Typical small case:

- 1× 4B semantic preparation;
- 1× 4B semantic verification;
- 0× 27B when semantics are clean and no RCA mechanism evidence exists.

TC12-class larger case:

- 2× 4B requirement-compilation batches;
- 1× 4B evidence annotation;
- 1× 4B semantic verification;
- 0× 27B if the compiled semantics verify cleanly.

If semantic verification finds a material mismatch, all mismatches are still resolved in **one** 27B arbitration call.

## Intake routing note

The structured TC12 fixture should use **Intake Routing = Auto** so deterministic section parsing bypasses source-availability/content-classification calls. `Always` remains an explicit user override and will intentionally incur those extra 4B calls.

## Regression coverage

v0.8.1 adds regressions for:

- `required_behavior.event = null` envelope normalization;
- bounded TC12 semantic-preparation batches;
- compact batch prompt size;
- independent detection of the live silent-condition-omission failure;
- updated adaptive routing with the mandatory fast semantic verifier;
- existing TC12 deterministic 1100/800/+300 ms violation;
- existing TC17 nested-condition violation and override non-applicability.

## Architecture compatibility

No v0.8 ownership boundary changes:

- LLMs interpret natural language;
- Python executes only verified semantic representations;
- Python owns final compliance;
- 27B semantic arbitration remains conditional and case-level;
- 27B RCA remains conditional and cannot modify compliance;
- original natural-language requirements are not resent to the RCA model by default.
