# RCA Analyst v1.8.6 Release Notes

**Application:** v1.8.6  
**Embedded RCA Core:** v0.8.5 candidate  
**Release type:** application observability/configuration repair + evidence-driven semantic hardening.

## Why this release exists

Live Dell and RunPod v1.8.5 runs exposed two different classes of defects.

Application/Web defects:

- completed pipeline updates could erase the previously stored Stage Input;
- stage data was presented primarily as raw JSON, including Verified Semantic Representation;
- batch result tabs were not populated per testcase and batch results were not published incrementally;
- per-testcase/per-stage performance aggregation was missing and failed calls were underrepresented;
- model discovery/test used persisted effective configuration rather than the endpoint currently typed in the Web form;
- deployment environment overrides could make a successful save appear to revert on the next reload/test;
- external llama.cpp/LM Studio/vLLM engine settings were presented more strongly than the backend's actual authority;
- active release/version references were inconsistent in several application locations.

Live semantic defects:

- TC17 repeatedly compiled `A AND (B OR C) AND D` into a materially different Boolean tree while the independent verifier still returned `VERIFIED`;
- TC17 semantic arbitration could explain evidence correctly in notes while returning compliance-linked facts with `OTHER`/missing executable fields;
- RunPod TC8/TC12/TC13/TC18 demonstrated repeated small-model schema-enum violations such as `HAS`, `REACHES`, `WAS`, and `CONTAINS`;
- Dell TC12 completed operationally but did not meet semantic acceptance and spent most runtime in an unsuccessful 27B arbitration retry.

These failures do **not** justify Python natural-language heuristics or weaker evidence rules. v1.8.6 therefore hardens contracts and model routing while preserving Python compliance authority.

## Application changes

### Persistent and structured Live Pipeline

- stage updates merge with existing stage state instead of replacing it;
- non-empty Stage Input/Output and structured `input_data`/`output_data` survive later status events;
- past stages remain inspectable after completion;
- complex JSON is rendered as labeled, nested human-readable structures with a Raw JSON forensic view;
- LLM semantic substages expose role, endpoint, model, transport, thinking/reasoning settings and token budget in their stage input.

### Complete batch result parity

- batch result JSON is persisted incrementally after every completed or failed testcase;
- a testcase selector drives Final Report, Validation, Canonical Input, Structured JSON, LLM Attempts, Repair Routing, logs, pipeline and statistics;
- Sequential Batch becomes an overall dashboard instead of the only useful batch result surface;
- failed case payloads remain available and contribute model statistics.

### Statistics

Per testcase, v1.8.6 aggregates:

- total elapsed time;
- model time and estimated Python time;
- model-call count;
- prompt/completion/reasoning/total tokens;
- retries;
- weighted generation throughput;
- breakdown by model role;
- requirement-result counts when available.

Per pipeline stage, the backend attaches:

- elapsed time;
- model call count/time;
- prompt/completion/reasoning/total tokens;
- retries;
- weighted generation throughput;
- models/endpoints used.

### Model discovery/configuration

- `POST /api/v1/models/discover` discovers models from the endpoint currently entered in the Web form; saving first is not required;
- `POST /api/v1/models/test` can test the current form values directly;
- if discovery returns exactly one model and the old form value is invalid for the endpoint, the UI selects the discovered model;
- active `RCA_*` model environment overrides are exposed through capabilities and shown explicitly in the UI;
- backend connection testing no longer destroys unsaved model/config edits;
- each run carries an explicit immutable `config_override` snapshot from the current form, so deployment environment variables remain defaults rather than silently preventing a one-run experiment.

### External inference-engine clarity

The v1.8.6 backend still does **not** own external llama.cpp/LM Studio/vLLM process lifecycle. Therefore:

- Web context/model-server fields are labeled as expected server metadata/checks;
- engine controls are capability-disabled unless a future deployment adapter explicitly declares backend ownership;
- changing a Web context field does not pretend to change a server launched with `llama-server -c ...`.

## RCA Core v0.8.5 changes

### Critical Semantic Model Routing

Requirement/evidence semantic preparation and independent semantic verification can be routed independently to either configured model role:

- `small` — Small / Utility model;
- `primary` — Primary model.

This is a capacity/transport choice only. Python remains authoritative for deterministic compliance. Utility intake, narrow repair and optional review roles can remain on the small model.

### Independent verifier structured fingerprint

The verifier must now reconstruct source semantics independently into structured fields:

- normative type;
- Boolean condition AST;
- trigger;
- required behavior;
- timing;
- persistence;
- relationships.

Python compares that source-derived structured fingerprint with the compiler IR. A `VERIFIED` label or prose agreement cannot suppress a structured mismatch. AND/OR child ordering is normalized only where logically commutative; regrouping remains detectable.

### Arbitration evidence replacement hardening

A compliance-linked arbitration evidence replacement is rejected when it:

- contains no facts;
- remains unresolved;
- leaves `temporal_semantics=OTHER`;
- lacks structured subject;
- uses `operator=OTHER` for executable state semantics;
- omits a required structured value;
- claims persistent state without a resolved non-empty `scope_id`.

Correct meaning written only in notes is not an executable repair.

### Evidence annotation contract

The v0.8.5 evidence prompt explicitly constrains operators to the schema enum. Model-invented words such as `HAS`, `REACHES`, `WAS`, or `CONTAINS` are not mapped by Python into semantic meaning. If the model cannot express a fact within the schema, it must keep the semantic item unresolved.

## Validation status

Release validation: **201 passed** in the working tree and **201 passed** from a clean freshly extracted release candidate. Compile/static checks, FastAPI smoke checks, Web JavaScript syntax, ZIP integrity and package-content audits are also release gates. Live-model validation remains required after release.

In particular, RCA Core v0.8.5 is **not frozen** until current live reruns demonstrate the expected TC17 and TC12 outcomes. v0.4.3 TEST-003 and v0.5.2 TC1–TC3 remain frozen regression anchors.
