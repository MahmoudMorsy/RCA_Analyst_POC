# RCA Analyst v1.8.7 Release Notes

**Application:** v1.8.7  
**Embedded RCA Core:** v0.8.6 candidate  
**Basis:** clean v1.8.6 release plus the live RunPod TC17 session `TEST-017_20260902_124822_cd1f59`.

## Why v1.8.7 exists

The first live TC17 rerun on v1.8.6 used Qwen3.8-27B Q5_K_M for critical semantic preparation and verification, a 32K model-server context, semantic output budget 12K, and UI thinking settings set to Off. The run proved that model capacity and context were no longer the primary failure.

The 27B correctly reconstructed the central TC17 Boolean condition, but the case still ended UNKNOWN / NOT EVALUABLE because several model-transport and structured-semantic contracts remained defective:

- `thinking_mode=off` was not translated into llama.cpp's request-level `chat_template_kwargs.enable_thinking=false`; large `reasoning_content` was returned anyway.
- Telemetry reported `reasoning_tokens=0` even while substantial reasoning text was present.
- Requirement compilation produced correct condition logic but incomplete `required_behavior` shells with provenance only and no executable signal/operator/value.
- The old structural-completion path regenerated large Requirement IRs rather than repairing only the broken fields, causing two 12K `finish_reason=length` attempts on TC17.
- Persistent language evidence was semantically recognized but returned without a concrete resolved scope, so Python correctly refused to execute it.
- Narrative/title/reporting ambiguity was too easily promoted to compliance-material unresolved evidence.
- Semantic arbitration understood the intended requirement semantics but returned anonymous executable predicates while source-clause semantic IDs were kept separately; the strict Python arbitration validator correctly rejected that pseudo-repair.

v1.8.7 fixes those boundaries without adding Python natural-language interpretation and without weakening the frozen evidence model.

## Application / transport changes

### Request-level Qwen thinking control

For OpenAI-compatible chat transport, explicit thinking modes are now propagated as provider chat-template arguments:

```json
{"chat_template_kwargs": {"enable_thinking": false}}
```

for Thinking Off, and `true` for Thinking On. A bounded compatibility fallback removes only this optional provider-specific field when an OpenAI-compatible server rejects it with HTTP 400/422.

This is transport behavior only; it does not alter RCA semantic authority.

### Reasoning observability

Model-call statistics now expose:

- `reasoning_content_present`;
- `reasoning_content_chars`;
- requested thinking mode;
- provider-reported reasoning tokens when available.

The application does not fabricate a reasoning-token count when the provider exposes reasoning text but reports zero reasoning tokens.

Per-case, per-role and per-stage aggregations include reasoning-content call/character counts so a provider silently ignoring Thinking Off is visible.

## RCA Core v0.8.6 changes

### Targeted Requirement IR structural completion

Structural completion is no longer a full Requirement IR regeneration step.

Python first identifies exact non-executable structured fields using the existing IR/source-clause inventory. The model receives only those target fields and returns a `RequirementStructuralPatchBatch`. Python rejects patches that:

- target an unknown requirement;
- duplicate a requirement patch;
- modify a field that was not requested;
- contain no requested repair.

Only explicitly targeted fields are replaced. Already-valid condition ASTs therefore cannot be overwritten merely because `required_behavior` or persistence is incomplete.

The completion call also has a bounded compact output budget rather than inheriting the full semantic-preparation output budget.

### Requirement compiler contract hardening

For signal/value obligations, `required_behavior` must contain all executable and provenance fields together:

- `semantic_id`;
- exact grounded `source_phrase`;
- signal;
- executable operator;
- value.

A provenance-only behavior shell is invalid.

Simple negative conditions such as `ServiceMode is not ACTIVE` should be represented as a grounded `NEQ` predicate. `NOT` remains for compound negation rather than requiring an invented positive source phrase.

Comparison values use plain literals rather than JSON serialized inside a string. Explicit persistence requires `required=true`; `shall remain ...` under an IF condition uses the explicit `WHILE_CONDITION` scope. Plain `shall be ...` does not gain invented persistence.

### Structural integrity hardening

Python now additionally detects structured cases where:

- source-clause inventory declares a condition but condition IR is missing;
- a mandatory/prohibitive source-clause inventory declares required behavior but behavior IR is missing;
- a signal-based required behavior uses `OTHER` or lacks a required value;
- persistence exists but `required=false`.

These checks operate only on existing structured IR/source-clause data. They do not parse requirement prose.

### Persistent evidence scope completion

Evidence annotations that choose `PERSISTENT_STATE` must have an executable scope:

- `scope.resolution=RESOLVED`;
- non-empty concrete `scope_id`.

If evidence explicitly states that a fact held throughout the complete/entire evaluated interval, the semantic annotator is instructed to use `CASE_EVALUATED_INTERVAL` and retain the grounding phrase. Other unresolved interval references remain unresolved.

Python now flags all persistent facts lacking a resolved concrete scope so targeted evidence completion can repair them instead of allowing a non-executable fact to remain silently incomplete.

### Evidence materiality correction

Narrative ambiguity is no longer compliance-material merely because an annotation references a requirement ID. Materiality is based on explicit evidence roles and structured requirement dependencies.

If an unresolved structured fact's subject is actually used by Requirement IR and its semantics/scope remain unresolved, Python still treats that fact as material. This preserves conservative compliance while preventing ticket titles, descriptions and reported-result narrative from blocking execution without a structured dependency.

### Arbitration provenance/executability contract

The existing strict arbitration validator is preserved. The prompt now explicitly requires every repaired executable semantic element to carry its own matching `semantic_id` and exact grounded `source_phrase`, together with executable fields. Separate source-clause prose/IDs cannot substitute for provenance on the actual executable node.

### Independent verifier remains authoritative only through Python comparison

The v0.8.5 source-derived semantic fingerprint mechanism remains. v0.8.6 aligns its contract with the compiler changes for negative predicates, literal comparison values and persistence fields. A verifier saying `VERIFIED` is still insufficient when Python detects a structured mismatch.

## What did not change

- Python does not map arbitrary natural-language operator synonyms into semantic meaning.
- Point state, transition and interval evidence remain distinct.
- Separate point samples do not become simultaneous evidence without correlation.
- Persistent state remains non-executable without concrete resolved scope.
- Missing evidence remains UNKNOWN / NOT EVALUABLE.
- Historical evidence remains non-normative.
- Hypotheses still require positive mechanism support.
- The Primary model cannot override Python deterministic compliance.
- Browser code contains zero RCA decision logic.
