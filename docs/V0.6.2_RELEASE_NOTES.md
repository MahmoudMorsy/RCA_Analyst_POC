# v0.6.2 release notes

v0.6.2 hardens the new multi-model intake path introduced in v0.6.0. It does not change frozen RCA evidence semantics.

## TC5 forced-intake defect

With `4B Intake Routing = Always`, Qwen3.5 correctly understood TC5 but returned YAML-like text. The manual completion parser then located the inner requirement JSON object and treated it as the entire structured response. Because `IntakeNormalization` has safe empty defaults, top-level sanitization converted that fragment into an empty but schema-valid intake object. Python then canonicalized zero requirements and stopped before the 27B stage.

## Fix

- Manual Qwen3.5 completions now receive the exact requested JSON Schema in their prompt.
- Structured parsing accepts only one top-level JSON object (after supported think/code-fence cleanup); embedded fragments are rejected.
- The existing one bounded retry is therefore used for YAML/prose/malformed responses.
- Terminal-only recovery remains limited to missing closing `]`/`}` delimiters and is no longer allowed to start from an embedded object.
- If forced intake still yields no source-backed requirements but deterministic parsing already found valid requirements, Python preserves that deterministic canonical path and surfaces the 4B stage as `attention` for inspection.
