# RCA Analyst v1.8.13 Release Notes

**Application:** v1.8.13  
**RCA Core:** v0.8.11 candidate

## Why v1.8.13 exists

The exact v1.8.12 RunPod session `RCA_20260903_110944_47ac48` completed all 17 requested cases with no batch-liveness failure and achieved **14/17 semantic acceptance**. TC12 and TC17 remained clean controls. TEST-007, TEST-015, TEST-016, TEST-018 and TEST-021 also passed after the v1.8.11/v0.8.10 fixes. The remaining failures were TEST-004, TEST-009 and TEST-019.

Those failures were traced to four bounded integration contracts rather than a need to redesign the semantic topology.

## Fixes

### 1. Explicit verifier target fields are authoritative

TEST-019 showed a verifier issue whose structured `target_fields` contained only `relationships`, while its explanatory prose also said that trigger and timing were already correct. v1.8.12 scanned that prose and incorrectly added `trigger` and `timing` as repair targets.

v1.8.13 uses explicit structured `target_fields` exactly when present. Description-based target inference remains only as compatibility fallback for structural issues that have no explicit targets.

### 2. Field-level admissible repair progress

TEST-004 showed that one omitted target field could cause valid sibling repairs to be discarded.

v1.8.13 changes repair admission without weakening semantic validation:

- targeted structural completion may apply the valid fields that were actually returned;
- omitted target fields remain unresolved and are rediscovered by the next bounded structural-integrity pass;
- arbitration likewise keeps valid targeted sibling repairs when another target is omitted;
- changed untargeted arbitration fields remain rejected;
- a zero-progress arbitration response is still rejected conservatively;
- Python never fills omitted semantic meaning from requirement prose.

### 3. Correlated current direct-observation closure in RCA packets

TEST-009 showed a compact-packet information loss: a selected requirement observation and an explicit current communication-loss observation were captured in the same `FAIL_POINT` snapshot, but the latter disappeared because it was not itself a compliance predicate.

v1.8.13 expands only the selected current snapshot:

- peers with the same explicit `observation_group` are included;
- peers at the exact same timestamp on the same explicit clock are included;
- unrelated direct observations remain excluded;
- Python does not infer causality or mechanism from the correlation.

### 4. Authoritative current-case compliance source gate

The v1.8.12 TEST-009 result also exposed a hidden invariant violation: historical semantic facts were able to enter the deterministic compliance fact pool and appear in current applicability/evaluation evidence IDs.

v1.8.13 admits language-derived deterministic facts only from:

- current `DIRECT_OBSERVATION` evidence, including current diagnostics;
- `REPORTED_OBSERVATION` evidence;
- `CURRENT_TICKET` evidence only when explicitly marked `scope_metadata=true`.

Historical evidence, system requirements, test instructions, hypotheses and ordinary ticket prose are non-normative for current compliance and are excluded from the execution fact pool.


### 5. Terminal state/session autosave ordering

Release gating exposed an intermittent application race: a very fast run could publish `COMPLETED` before `_auto_session()` persisted `session_id`, so a client polling terminal status could briefly receive a terminal run with an empty session ID. v1.8.13 prepares terminal metrics and the session first, then publishes `COMPLETED`/`FAILED`/`CANCELLED`. This is an application-lifecycle fix and does not affect RCA semantics.

## What did not change

- overall v0.8 semantic compiler → verifier → Python compliance topology;
- state / transition / interval evidence distinctions;
- point correlation rules;
- persistence scope rules;
- deterministic timing authority;
- historical evidence remains available for RCA precedent, just not compliance truth;
- one-call Primary arbitration budget;
- conditional RCA synthesis;
- Web/backend run ownership, reconnect, batch continuation and failure forensics;
- v1.8.12 Models & Inference discovery/context/real inference-test behavior.

## Regression coverage

- historical non-normativity in deterministic compliance evidence.
