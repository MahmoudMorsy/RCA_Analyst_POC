# RCA Analyst POC v0.6.4 — Structured 4B Final Review

v0.6.4 addresses the remaining TC5 false-positive linguistic-review finding observed in v0.6.3 without moving semantic authority away from Python.

## Final-review architecture

The Qwen3.5-4B final reviewer no longer makes one broad free-form contradiction judgment. For each requirement it must first classify what the current relevance sentence claims about:

- evidence relevance: `RELEVANT`, `NOT_RELEVANT`, or `UNDETERMINED`;
- evidence sufficiency: `SUFFICIENT`, `INSUFFICIENT`, `NOT_REQUIRED`, or `UNDETERMINED`;
- implied evaluation status: `SATISFIED`, `VIOLATED`, `NOT_EVALUABLE`, `NO_COMPLIANCE_VERDICT`, `NOT_STATED`, or `UNDETERMINED`;
- overall verdict consistency and whether a wording issue actually exists.

Python compares those extracted language claims with the already validated authoritative structure before accepting any relevance rewrite. This keeps the model responsible for understanding language while making the final decision mechanically checkable.

The combination `RELEVANT + INSUFFICIENT + NOT_EVALUABLE` is explicitly valid. It must not be treated as a contradiction. This directly protects TEST-005, where the visible response transition is relevant to REQ-401 but incomplete event coverage prevents a conclusive timing verdict.

## Independent final-review model settings

The final 4B reviewer now has settings separate from 4B intake/repair.

Default final-review settings:

- Reasoning: `Low`
- Thinking: `provider/default`
- Transport: `OpenAI chat`
- Max output: `1200`

Intake and field repair remain non-thinking by default and continue to use their existing fast settings. The GUI exposes the final-review reasoning, thinking, and transport controls separately.

## Version-history log

A new root-level `VERSION_HISTORY.md` provides a chronological transition log from the earliest tracked v0.2.0 release through the current release. `CHANGELOG.md` remains the newest-first release log.

## Semantic boundary

No frozen evidence semantics are weakened in this release. Python remains authoritative for evidence identity/provenance, timing calculations, state/transition/interval semantics, applicability/evaluation consistency, verdict enforcement, repair allowlists, and the final gate.
