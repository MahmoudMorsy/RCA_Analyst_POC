# RCA Analyst v1.8.12 Release Notes

**Application:** v1.8.12  
**RCA Core:** v0.8.10 candidate — unchanged from v1.8.11

## Why v1.8.12 exists

v1.8.11 exposed an application-only regression in **Models & Inference** while preparing the next RunPod full-suite validation:

- **Discover at Endpoint** reported success when the endpoint was reachable but no model was loaded/advertised;
- changing an endpoint could leave a stale model ID and discovery did not reliably resolve provider catalog variants;
- runtime context discovery depended only on optional `/v1/models` metadata and therefore missed llama.cpp context exposed through `/props`;
- **Test Model** only checked model listing and provided feedback mainly through a transient toast, so it could appear to do nothing and did not prove inference readiness.

No RCA semantic/compliance behavior changed in this release.

## Fixes

### Strict endpoint discovery

`POST /api/v1/models/discover` now distinguishes:

- `AVAILABLE` — one or more models are advertised;
- `NO_MODELS` — endpoint is reachable but advertises no loaded models;
- `UNAVAILABLE` — endpoint/catalog request failed.

An empty catalog is no longer treated as success.

### Model-ID resolution

OpenAI-compatible catalog normalization now accepts both standard `data[].id` and compatible `models[].name`/`models[].model` shapes. When exactly one model is advertised, the Web UI resolves that model into the form automatically. Editing the endpoint invalidates stale endpoint-specific model/context data until discovery is run again.

### Runtime context discovery

Discovery keeps explicit catalog metadata and additionally performs observational metadata probes where supported. For llama.cpp, `/props` `default_generation_settings.n_ctx` is used as the runtime context when `/v1/models` does not expose it. Compatible LM Studio metadata surfaces are also queried without making those optional probes fatal.

The discovered context is displayed and populated into the model context metadata field. It remains metadata/check information only; RCA Analyst does not reconfigure an already-running external model server.

### Real inference test

**Test Primary Model** / **Test Small Model** now:

1. requires at least one advertised model;
2. verifies that the selected model is actually advertised;
3. performs a minimal one-token OpenAI-compatible `/chat/completions` inference probe;
4. reports persistent PASS/FAIL status directly in the model panel, in addition to the normal toast;
5. reports discovered model/context metadata with the test result.

This distinguishes server reachability from actual model readiness.

## Validation

New v1.8.12 regressions cover:

- llama.cpp-style `models[].name` catalog normalization;
- `/props` runtime-context discovery;
- reachable endpoint with no loaded model;
- automatic single-model resolution after endpoint change;
- real minimal inference probing;
- persistent Web discovery/test state and endpoint invalidation.

Final release gate: **248/248 tests passed** in the working tree and **248/248 passed** from a clean fresh extraction of the exact release ZIP. Python compile, Web JavaScript syntax, FastAPI `/health`/`/config`/`/capabilities`, ZIP integrity and archive-hygiene checks also pass.

RCA Core v0.8.10 and all frozen evidence/compliance rules are unchanged.
